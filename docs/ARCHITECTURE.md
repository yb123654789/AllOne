# AllOne 架构设计文档

> 版本：0.1

## 1. 技术选型

- **框架**：Flutter（一套 Dart 代码覆盖 Android / Windows / iOS）
- **状态管理**：Riverpod（成熟、可测试、模块化）
- **本地存储**：文件系统 + JSON（格式通用、可 U 盘直接备份），配以内存索引
- **富文本**：`flutter_quill`（成熟编辑器）
- **离线地图**：`flutter_map` + 本地瓦片（离线地图方案）
- **数据库（可选索引）**：Drift/SQLite（仅用于加速检索，不作为唯一存储）

## 2. 模块化分层

```
┌─────────────────────────────────────────────────┐
│                  app（壳 / 导航）                 │
│       底部导航：日记 | 待办 | 习惯 | 记账 | 日历   │
└───────────────┬─────────────────────────────────┘
                │ 依赖
┌───────────────▼─────────────────────────────────┐
│                  core（核心层）                   │
│  · 数据访问层（统一文件读写）                     │
│  · 存储引擎（目录结构 / JSON 序列化）             │
│  · 通用组件（富文本、多媒体、地图、时间戳等）      │
│  · 备份/恢复引擎                                 │
└──────┬──────────┬──────────┬──────────┬──────────┘
       │          │          │          │
┌──────▼───┐ ┌────▼─────┐ ┌───▼────┐ ┌──▼───────┐ ┌───▼────┐
│ 日记模块  │ │ 待办模块 │ │ 习惯模块│ │ 课程表模块│ │记账模块 │
│ feature_ │ │feature_  │ │feature_│ │feature_   │ │feature_ │
│ diary    │ │todo      │ │habit   │ │schedule   │ │ledger   │
└──────────┘ └──────────┘ └────────┘ └───────────┘ └────────┘
       │          │          │          │
       └──────────┴────┬─────┴──────────┘
                       │ 只读
                ┌──────▼──────┐
                │  日历模块    │  （聚合视图）
                │ feature_cal │
                └─────────────┘
```

- **feature_***：每个功能一个独立 Dart 包/目录，拥有自己的数据模型与页面，互不引用对方内部实现。
- **core**：提供公共能力，所有 feature 依赖 core，core 不依赖任何 feature —— 实现风险隔离。
- 任一模块崩溃/出错不影响其余模块（各自 try/catch + 独立存储文件）。

## 3. 目录结构（Flutter 项目）

```
AllOne/
├── lib/
│   ├── main.dart                 # 应用入口
│   ├── app.dart                  # 根组件、主题、导航壳
│   ├── core/                     # 核心层
│   │   ├── storage/              # 存储引擎（目录、读写、序列化）
│   │   ├── models/               # 通用模型（Id、时间戳、附件、标签）
│   │   ├── widgets/              # 通用组件（多媒体、地图、编辑器）
│   │   ├── backup/               # 备份/恢复引擎
│   │   └── utils/                # 工具（日期、文件大小、加密）
│   ├── features/
│   │   ├── diary/                # 日记模块
│   │   ├── todo/                 # 待办模块
│   │   ├── habit/                # 习惯模块
│   │   ├── schedule/             # 课程表模块
│   │   ├── ledger/               # 记账模块
│   │   └── calendar/             # 日历模块（聚合）
```

## 4. 数据流

1. 用户操作 → Feature 页面 → Feature 的 Controller（Riverpod）
2. Controller 调用 core 存储引擎 → 写 JSON 文件到数据目录
3. 存储引擎维护内存索引 → 界面响应式更新
4. 日历模块通过 core 提供的「只读聚合查询」读取各模块数据

## 5. 风险隔离策略

- 每个模块的数据在独立子目录，JSON 文件独立 → 单文件损坏不影响其他模块。
- 写文件采用「先写临时文件 + 原子替换」，避免写一半损坏。
- 启动时按模块逐项加载，单模块失败仅降级该模块。
- 所有 IO 均有 try/catch，错误降级提示而非崩溃。

## 6. 备份 / 恢复

- **U 盘手动备份**：一键导出整个数据目录（或压缩为 zip）到外部存储。
- **恢复**：从备份 zip / 目录导入。
- 导出格式保持 JSON/附件原样，保证跨设备可读。
